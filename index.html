Your LLM reviews its own code and misses the same bugs it wrote. This splits one task across different models — a coder writes, a critic catches, a judge checks — so no single model's blind spot becomes your bug.

The idea

Give each role to a different model and run them against each other. A judge checks every answer against the task before anything reaches you.

What it caught in practice

A coder produced a clean parseClusterConfig. A different model then found eight problems it never saw:

  • ✗ duplicate machines allowed — routing conflict in a real cluster
  • ✗ reserved IPs accepted — 0.0.0.0, 127.0.0.1 as machine addresses
  • ✗ array slips past the object check — misleading error
  • ✗ unsafe cast before type validation
  • ✗ whitespace leak in names
  • ✗ no orchestrator required
  • ✗ misleading "Invalid JSON" error
  • ✗ dead code + missing bounds

The synthesis fixed them. Neither model alone produced the result — different blind spots beat one model doing both jobs.

What you get
